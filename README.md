# VK-бот с AI-ответами

Репозиторий: [github.com/fox67rus/vkbot](https://github.com/fox67rus/vkbot)

Бот для сообщества ВКонтакте: ведёт **главное меню** с услугами, прайс-листом и
кнопкой связи с менеджером, приветствует новых участников беседы и отвечает на
входящие сообщения через AI-провайдер **ProxyAPI** (модель `gpt-5.4-mini`).

События получаются через **LongPoll API** — свой сервер не нужен.

- **Главное меню** в личных сообщениях: список услуг, описание каждой услуги,
  прайс-лист, «О нас», «Помощь» и кнопка «Связаться с менеджером» (открывает
  ссылку на менеджера или звонок — как задано в контенте).
- Весь контент — в [`data/content.json`](data/content.json): правьте тексты,
  услуги и цены без изменения кода.
- **Приветствие** вступает в беседу — по событию `chat_invite_user` / `chat_invite_user_by_link`.
- **Личные сообщения** — первое сообщение открывает меню с приветствием, на любой
  другой текст отвечает AI (под ответом всегда кнопка «📋 Меню»). Повторные
  открытия меню («Назад», «Меню», команда «меню») показывают короткий заголовок,
  а не приветствие заново.
- **Беседа** — отвечает при упоминании (`@имя_бота ...`); команды меню
  («меню», «услуги», «цены», «менеджер») работают и здесь — текстом, потому что
  ВК не показывает клавиатуры в беседах.
- История диалога хранится в памяти процесса (последние N пар реплик), после рестарта очищается.

Выжимка документации vkbottle — в [docs/](docs/README.md).

## Быстрый старт

```powershell
# 1. Зависимости (в venv уже установлены)
& .\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

# 2. Ключи: скопируйте шаблон и заполните
Copy-Item .env.example .env
notepad .env

# 3. Запуск (LongPoll, останавливается Ctrl+C)
python bot.py
```

Минимум нужных переменных — `VK_TOKEN` (ключ сообщества, *Управление → Работа с API →
Ключи доступа*) и `PROXYAPI_API_KEY` (https://console.proxyapi.ru → API-ключи).
Если их нет, бот завершится с кодом `1` и скажет, чего не хватает.

## Тесты

```powershell
& .\venv\Scripts\Activate.ps1
python -m pytest
```

Тесты не ходят в VK и не тратят баланс: AI проверяется против мок-сервера,
правила — против синтетических сообщений.

## Как это устроено

**LongPoll.** `bot.run()` вызывает `run_polling()` → `BotPolling.listen()`: клиент
периодически опрашивает VK и рассылает `updates` по хендлерам. Параметры по умолчанию
`wait=25`, `skip_old_events=True` (подробнее — [docs/02-longpoll.md](docs/02-longpoll.md)).

**Маршрутизация.** Каждый входящий `MessageNew` проверяется по правилам каждого
хендлера, пока не найдётся подходящий. Лейблеры подключаются в порядке
`bot.py`: приветствие → **меню** → AI, поэтому кнопка или команда никогда не
уходит в AI.

| Хендлер | Правила | Когда срабатывает |
|---|---|---|
| `greet_new_member` | `ChatActionRule` | в беседу вошёл участник |
| `on_menu_button` … `on_help_button` | `PayloadRule` / `PayloadMapRule` | нажата кнопка меню (`{"cmd": "..."}`) |
| `on_alias_command` | `func`: текст ∈ командам меню | в ЛС написали «меню», «цены», «услуги»… |
| `on_chat_alias_command` | `MentionRule(mention_only=False)` + `func` | то же в беседе, с упоминанием бота |
| `private_message_handler` | `PeerRule(from_chat=False)` + `FromUserRule` + не payload/не команда | первое сообщение → приветствие с меню, дальше любой текст → AI |
| `chat_message_handler` | `PeerRule(from_chat=True)` + `MentionRule(mention_only=False)` + `FromUserRule` + не команда | бота упомянули в беседе |

Два момента, без которых ничего не работает:

1. `bot.labeler.message_view.replace_mention = True` — вырезает `[club123|Имя]` из
   текста до правил. Без этого `message.mention`/`is_mentioned` не заполняются и
   `MentionRule` никогда не сработает. Заодно модель видит чистый вопрос.
2. `MentionRule(mention_only=False)` — по умолчанию правило ловит только голое
   упоминание без текста (`@бот`). Нам нужно «упомянул → отвечаю».

**Диалог с AI.** Хендлер дописывает реплику пользователя в историю, отправляет
`[system] + история` в `POST /v1/chat/completions`, ответ сохраняет как `assistant`.
При ошибке пользовательская реплика откатывается, чтобы история не засорялась.

**Отказоустойчивость.**

| Ситуация | Поведение |
|---|---|
| 429 / 500 / 502 / 503 / 504 | повтор с экспоненциальной задержкой (`AI_MAX_RETRIES`) |
| 400 и в запросе были `temperature`/`max_tokens` | повтор без этих параметров |
| Сетевая ошибка / таймаут | повтор, затем `AIClientError` |
| 402 / 404 / прочие | `AIClientError` с текстом из `detail` или `error.message` |
| Ошибка AI | бот отвечает «Не получилось получить ответ…», история откатывается |
| Ответ длиннее 4096 | `message.answer()` сам режет на части |
| Ошибка VK (901/902/903, прочие) | логируется, поллинг не падает |

## Контент: меню, услуги, прайс, менеджер

Все пользовательские тексты лежат в **[data/content.json](data/content.json)** —
правьте их там, код трогать не нужно (изменения применяются после перезапуска
бота или по `content.reset_content()`).

| Раздел | Что хранит |
|---|---|
| `menu` | приветствие при первом открытии (`welcome`), заголовок повторных открытий (`title`, необязательный), заголовок списка услуг (`services_text`), подписи кнопок «Назад»/«Меню» и сам список кнопок (`buttons`) |
| `services` | услуги: `id`, `title`, `short`, `description`, `price`, `duration` |
| `price` | заголовок и сноска прайса + `order` — в каком порядке показывать услуги |
| `manager` | контакты: `name`, `greeting`, `phone`, `hours`, `link` + `link_label` (кнопка-ссылка) |

Кнопки меню (`menu.buttons[].id`) умеют открывать только эти экраны:
`services`, `price`, `manager`, `about`, `help`. Для `about` и `help` обязателен
пункт `text` — это готовый текст экрана.

```jsonc
// пример: поменять цену — правка одной строки
{ "id": "web", "title": "Разработка сайта", "description": "…", "price": "от 90 000 ₽" }
```

Файл проверяется при старте (`content.py`): отсутствует раздел, дублируется
`id` услуги, кнопка ссылается на несуществующую услугу или менеджер остался
без телефона и ссылки — бот завершится с кодом `1` и напишет, что именно не так.

## Настройки

Все переменные, их значения по умолчанию и комментарии — в [.env.example](.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VK_TOKEN` | — | ключ доступа сообщества (обязательна) |
| `PROXYAPI_API_KEY` | — | ключ ProxyAPI (обязательна) |
| `PROXYAPI_BASE_URL` | `https://api.proxyapi.ru/v1` | базовый адрес провайдера |
| `AI_MODEL` | `openai/gpt-5.4-mini` | модель, полный id `<вендор>/<модель>` |
| `AI_SYSTEM_PROMPT` | промпт ассистента | системная инструкция; пусто → без промпта |
| `AI_TEMPERATURE` | `0.7` | пусто → не отправлять параметр |
| `AI_MAX_TOKENS` | `1000` | пусто → не отправлять параметр |
| `AI_TIMEOUT` | `60` | таймаут запроса, с |
| `AI_MAX_RETRIES` | `3` | число повторов |
| `AI_HISTORY_PAIRS` | `10` | глубина истории (пар реплик на пользователя) |
| `GREETING_TEXT` | ... | приветствие, `{name}` → имя участника |
| `BOT_GREETING_TEXT` | ... | когда в беседу добавили самого бота |
| `LOG_LEVEL` | `INFO` | уровень логирования |

Изменение модели или провайдера — правка одной строки в `.env`, код трогать не нужно.
Тексты меню, описания услуг, цены и контакты менеджера живут в
[data/content.json](data/content.json), а не в `.env`.

## Ограничения

- История живёт только в памяти: после рестарта диалог начинается заново.
- В беседе контекст общий на пару «диалог + автор», а не на всю беседу.
- Отвечают только на текст: вложения и картинки не обрабатываются.
- Callback API не используется — только LongPoll.
- ВК не показывает клавиатуры в беседах: там меню работает текстовыми
  командами («меню», «услуги», «цены», «менеджер»).
- Память приветствий (`menu._welcomed`) и контент живут в памяти процесса:
  после рестарта первый собеседник снова получит приветствие с меню.
- Правка `data/content.json` применяется после перезапуска бота.
